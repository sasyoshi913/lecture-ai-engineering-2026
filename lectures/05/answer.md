# 第5回 演習・宿題

## 演習

### 1. 各探索・コンテキスト投入方式の比較結果
同じ質問「`第2回の説明では、LoRAは何を固定し何を学習しますか? QLoRAは何を加えますか?`」（モデル: `gemini-3.5-flash-lite`）で4つの経路を実行し、回答・根拠・時間・トークン数・生成API推定費用を比較した[cite: 75, 78, 81, 84, 87]。

| 経路 | 正答 / 引用根拠 | 時間（秒） | 入力 / 出力 tokens | モデル応答回数 | 生成API推定 USD |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **全文投入（`--full-context`）** | 正答 / 第2回・PDF p.51-52（全9資料・227,971文字投入） | 7.36 | 117,025 / 218 | 1回 | $0.035652 |
| **ベクトル検索（基本RAG / `TOP_K=5`）** | 正答 / 第2回・PDF p.51, p.52 | 16.33 | 3,116 / 195 | 2回 | $0.001422 |
| **Tree（`--tree` / 目次探索）** | 正答 / 第2回・PDF p.52 | 19.13〜27.13 | 9,214 / 322〜339 | 5回 | $0.003569〜$0.003612 |
| **Graph（`--graph` / 周辺・共通用語）** | 正答 / 第2回・PDF p.51, p.52 | 10.49 | 5,773 / 241 | 2回 | $0.002334 |

### 2. 観察と気づき
- **全文投入 vs ベクトル検索**: 全文投入は1回のモデル応答で正確に答えられたが、入力トークンが `117,025 tokens`、費用が `$0.035652` と、ベクトル検索（`3,116 tokens` / `$0.001422`）と比べて**トークン数・費用ともに約25〜37倍**かかった。
- **Tree探索の特徴**: `browse_tree` を4回連続で呼び出し（一覧 → `lec02-main` → 章 `lec02-main-s045` → ページ `lec02-main-p052`）、ピンポイントで最も重要な p.52 の本文（717文字）だけにたどり着いた。一方で、階層を順にたどるためモデル応答回数が5回と多くなり、応答時間（19〜27秒）と入力トークン（9,214 tokens）がベクトル検索より増加した。
- **Graph探索の特徴**: 入口ページ（`lec02-main-p052`）から前後ページや共通用語をたどることで、単一ページだけでなく関連する p.51 の文脈もあわせて取得できた（入力 5,773 tokens / $0.002334）。

## 宿題

- **取り組んだレベル**: 基礎[cite: 90, 98]
- **やったこと**:
  `app/config.py` の検索件数設定 `RAG_TOP_K`（初期値 `5`）を変更し、他の条件（質問文「`第2回の説明では、LoRAは何を固定し何を学習しますか? QLoRAは何を加えますか?`」、対象資料、モデル `gemini-3.5-flash-lite`）を揃えたまま `--trace` 付きでベクトル検索を実行し、変更前後の挙動・回答・引用根拠・コストを比較した[cite: 88, 91, 99]。
  - 変更パターン1: `RAG_TOP_K = 1` に削減[cite: 88, 91, 99]
  - 変更パターン2: `RAG_TOP_K = 10` に増加[cite: 88, 91, 99]

- **結果（変更前後の比較）**:

| 設定（`RAG_TOP_K`） | ツール呼び出しと引数 | 引用根拠 | 時間（秒） | 入力 / 出力 tokens | 生成API推定 USD |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **変更前（`RAG_TOP_K = 5`）** | `search_materials({'query': 'LoRA 固定 QLoRA'})` (1回) | 第2回・PDF p.51, p.52 | 16.33 | 3,116 / 195 | $0.001422 |
| **変更後1（`RAG_TOP_K = 1`）** | `search_materials({'query': 'LoRA 固定 学習 QLoRA 加える'})` (1回) | **第2回・PDF p.52 のみ** | 10.75 | **1,191** / 201 | **$0.000860** |
| **変更後2（`RAG_TOP_K = 10`）** | `search_materials({'query': 'LoRA 固定 学習 QLoRA 加える'})` (1回) | 第2回・PDF p.51, p.52 | 5.88 | **5,189** / 239 | **$0.002154** |

- **気づき・疑問**:
  - **単一ページで完結する質問での効率性**: 今回の質問のように答えの核心が特定の1スライド（第2回・PDF p.52）に集約されている場合、`RAG_TOP_K = 1` に減らしても正答に必要な根拠を欠かすことなく取得でき、入力トークン数を約62%削減（3,116 → 1,191 tokens）、生成API費用も約40%削減（$0.001422 → $0.000860）できた。
  - **件数を増やすトレードオフ**: `RAG_TOP_K = 10` に増やすと、周辺スライド（p.51など）の情報も含めて網羅的に根拠を引用できる安心感がある一方、入力トークン数とコストが約1.5倍（`TOP_K=1` 比では約4.3倍）に膨らむ。1ページ1チャンク設計の資料では、複数のスライドにまたがる比較質問か、単一スライドの定義質問かによって適切な `RAG_TOP_K` の設定値が変わることを実感した[cite: 73, 86]。
