# 第3回 解答

## 演習

- **第1回（素のLLM）とエージェントの回答の違い**:
  - 第1回（`app.ask`）の素のLLMは講座固有の用語集（`data/glossary.json`）を知らないため、「AIE2026の講座の宿題にある『3レベル』とは何ですか？」と聞いても「分からない」と答えるか、一般的な推測で回答していた。
  - 第3回（`app.agent`）のエージェントは、答える前に `search_glossary` ツールを使って用語集の `homework-levels` を検索するため、「基礎・実装・発展の3つのレベルがあり、どれか1つに取り組めば完了する」という講座固有の定義に沿って正確に回答し、最後に関係する回（第1回）を示した。

- **`--trace` で見えたツール呼び出し（ツール名と引数）**:
  - `"LoRA と QLoRA の違いは?"` を実行した際、以下のように `search_glossary` が1用語ずつ計2回呼ばれた。
    - `[tool call] search_glossary({'query': 'LoRA'})`
    - `[tool call] search_glossary({'query': 'QLoRA'})`
  - `"第2回の内容から確認問題を1問出して"` を実行した際は、追加した `make_quiz` が以下のように呼ばれた。
    - `[tool call] make_quiz({'lecture': 2})`

- **1つの質問でのLLMの呼び出し回数（`requests`）**:
  - `requests=2`（`tool_calls=2` または `1`）。1回目のLLM呼び出しでどのツールをどの引数で呼ぶかを判断してツール実行を依頼し、プログラム側で実行したツールの返り値（`tool return`）を受け取ってから、2回目のLLM呼び出しで最終的な回答文を生成している。

- **追加したツールと、docstring に書いた説明**:
  - 追加したツール: `make_quiz(lecture: int) -> str`（指定した回の用語を用語集から集めてランダムに1つ選び、`{"question": "「○○」の意味は？", "answer": "..."}` のJSON文字列を返す関数）
  - docstring に書いた説明:
    `指定した回の用語から1つを選び、確認問題と答えを返す。「第2回の確認問題を出して」のように、復習用の問題を求められたときに使う。`

## 宿題

- **取り組んだレベル**: 基礎
- **やったこと**:
  一度に1か所だけ指示を変更し、同じ質問 `"LoRA と QLoRA の違いは?"` を `--trace` 付きで実行してベースライン（変更前）と比較した。
  1. **実験1（INSTRUCTIONS の変更）**: `app/agent.py` の `INSTRUCTIONS` から `- 用語や講座に固有のことを答える前に、必ず search_glossary で用語集を確認する。` の1行を削除した。
  2. **実験2（docstring の変更）**: `INSTRUCTIONS` を元に戻したうえで、`app/tools.py` の `search_glossary` の docstring にある `query には調べたい用語を1つだけ入れる（例: "LoRA"）。` を `query には調べたい用語をスペース区切りでまとめて入れる（例: "LoRA QLoRA"）。` に書き換えた。
- **結果**:
  | 条件 | ツール呼び出し回数 (`tool_calls`) | LLMリクエスト数 (`requests`) | 入力トークン数 (`input_tokens`) | 出力トークン数 (`output_tokens`) | 挙動の変化 |
  | :--- | :--- | :--- | :--- | :--- | :--- |
  | **変更前（ベースライン）** | 2回 | 2回 | 1198 | 231 | `'LoRA'` と `'QLoRA'` を別々に検索し、両方の定義をもとに違いを回答した。 |
  | **実験1（INSTRUCTIONS 削除）** | 2回 | 2回 | 1150 | 197 | 削除した1行分の入力トークンが減ったのみで、変更前と同じく `'LoRA'` と `'QLoRA'` を別々に2回検索して回答した。 |
  | **実験2（docstring 変更）** | **1回** | 2回 | **901** | 197 | `search_glossary` の呼び出しが **1回（まとめて検索）に減少**し、ツール返却値が1回分になったことで入力トークン数も1198→901へ大幅に減少した。 |
- **気づき・疑問**:
  - 実験1で `INSTRUCTIONS` から検索強制の指示を消しても `tool_calls=2` のまま変わらなかったのは、`app/tools.py` の docstring 側に「答える前に使うこと。query には調べたい用語を1つだけ入れる」という指示が残っており、モデルがツールの説明文を読んで自律的に判断したためだと分かった。
  - 実験2で docstring の `query` の指定を「まとめて入れる」に変えると、モデルが即座に指示に従ってツール呼び出しを `tool_calls=1` にまとめた。エージェントのツール選択や引数の渡し方を制御するうえで、システムプロンプト（`INSTRUCTIONS`）だけでなく各ツールの docstring の書き方が直接的かつ強力に効くことを実感した。
